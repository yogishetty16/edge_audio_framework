## Architecture Overview

The framework is structured in four layers:

```
Layer 1: Audio Input
    Microphone (live) or WAV file --> core/audio_io.py --> Normalized waveform

Layer 2: Parallel Task Execution
    Waveform --> 14 independent AI tasks running in parallel via ThreadPoolExecutor

Layer 3: Agent Decision Engine
    All task outputs --> agent/audio_agent.py --> Single unified decision

Layer 4: Persistent Memory
    Decision --> agent/memory.py --> JSONL timeline (agent_memory/events.jsonl)
```

Every task is a standalone Python module inside the `tasks/` directory. Each task receives the same audio waveform and returns a structured result. The agent then fuses all results into one actionable decision.

## AI Models and Tasks

### Task 1: Voice Activity Detection (VAD)

| Property | Value |
|----------|-------|
| File | `tasks/vad.py` |
| Model | Silero VAD v4 |
| Source | `snakers4/silero-vad` (PyTorch Hub) |
| Size | ~5 MB |
| Speed | Less than 1 millisecond |
| Input | Raw audio waveform at 16kHz |

**What it does:**
Detects whether a human voice is present in the audio window. It outputs a speech ratio (0.0 to 1.0) indicating what percentage of the recording contains speech, and a boolean flag indicating whether speech was detected.

**Output fields:**
- `is_speech` -- True if speech is detected above the threshold
- `speech_ratio` -- Percentage of the window that contains speech (e.g., 0.85 = 85%)
- `speech_duration_sec` -- Exact duration of detected speech in seconds
- `segments` -- List of start/end timestamps for each speech segment

**Why it matters:**
VAD is the gateway task. If no speech is detected, the agent skips speech-dependent follow-up tasks (ASR, emotion) and routes to environmental tasks instead. This saves compute on edge hardware.

### Task 2: Automatic Speech Recognition (ASR)

| Property | Value |
|----------|-------|
| File | `tasks/asr.py` |
| Model | Faster-Whisper (CTranslate2 INT8 quantized) |
| Source | OpenAI Whisper `base` model |
| Size | ~74 MB |
| Speed | ~1 second for 5 seconds of audio |
| Input | Raw audio waveform |

**What it does:**
Transcribes spoken words into text. Uses OpenAI's Whisper architecture but runs through CTranslate2 with INT8 quantization for maximum speed on CPU-only edge devices.

**Output fields:**
- `text` -- Full transcription of the spoken words
- `language` -- Detected language code (e.g., "en" for English)
- `segments` -- Word-level timestamps with confidence scores

**Why it matters:**
The transcript is used by the agent to detect safety-related keywords like "help", "fire", "emergency", "stop", and "evacuate". If any alert keyword appears in the transcript, the agent escalates the event to HIGH priority.

---

### Task 3: Keyword Spotting

| Property | Value |
|----------|-------|
| File | `tasks/keyword_spotting.py` |
| Model | MIT Audio Spectrogram Transformer (AST) |
| Source | `MIT/ast-finetuned-speech-commands-v2` |
| Size | ~350 MB |
| Speed | ~10 seconds |
| Input | Raw audio waveform |

**What it does:**
Classifies audio into 35 speech commands: yes, no, up, down, left, right, on, off, stop, go, zero through nine, and others. Unlike ASR which transcribes free-form speech, keyword spotting is trained to detect specific trigger commands with high accuracy.

**Output fields:**
- `top_label` -- Most likely keyword (e.g., "stop")
- `top_score` -- Confidence score (0.0 to 1.0)
- `all_scores` -- Scores for all 35 commands

**Why it matters:**
Critical for detecting spoken commands without running full transcription. The agent cross-references keywords like "stop" and "go" against a configurable alert keyword list. If a match is found above the confidence threshold (default 50%), it raises a risk signal.

### Task 4: Speaker Identification

| Property | Value |
|----------|-------|
| File | `tasks/speaker_id.py` |
| Model | SpeechBrain ECAPA-TDNN |
| Source | `speechbrain/spkrec-ecapa-voxceleb` |
| Size | ~80 MB |
| Speed | ~1 second |
| Input | Raw audio waveform |

**What it does:**
Extracts a speaker embedding vector and counts how many distinct speakers are present in the audio window. Can also compare two audio samples to determine if they contain the same speaker.

**Output fields:**
- `num_speakers` -- Number of distinct speakers detected
- `embeddings` -- 192-dimensional speaker embedding vectors
- `similarity_score` -- Cosine similarity between two speaker samples (when comparing)

**Why it matters:**
Used for access control, attendance tracking, and forensic analysis. In industrial settings, knowing how many people are present in a restricted area provides critical context for safety decisions.

### Task 5: Emotion Detection

| Property | Value |
|----------|-------|
| File | `tasks/emotion.py` |
| Model | SUPERB HuBERT-base |
| Source | `superb/hubert-base-superb-er` |
| Size | ~90 MB |
| Speed | ~2 seconds |
| Input | Raw audio waveform |

**What it does:**
Classifies the emotional state of the speaker from their voice. Detects emotions such as angry, happy, neutral, sad, and surprise based on acoustic features like pitch, energy, and speaking rate.

**Output fields:**
- `top_emotion` -- Detected emotion label (e.g., "angry")
- `top_score` -- Confidence score (0.0 to 1.0)
- `all_scores` -- Scores for all emotion categories

**Why it matters:**
The agent treats certain emotions as stress indicators. If angry, fearful, or sad emotions are detected above 45% confidence, the agent adds a "stressed_speech" risk signal. Combined with other signals, this can escalate an event from LOW to HIGH priority.

### Task 6: Speech Quality Assessment

| Property | Value |
|----------|-------|
| File | `tasks/speech_quality.py` |
| Model | Custom DSP (no neural network) |
| Source | Built-in signal processing algorithms |
| Size | 0 MB (pure math) |
| Speed | Less than 1 millisecond |
| Input | Raw audio waveform |

**What it does:**
Estimates the perceptual quality of the audio using a DNSMOS-inspired algorithm. Computes Signal-to-Noise Ratio (SNR), checks for clipping, and assigns a Mean Opinion Score (MOS) from 1.0 (unusable) to 5.0 (studio quality).

**Output fields:**
- `dnsmos` -- Predicted Mean Opinion Score (1.0 to 5.0)
- `snr_db` -- Signal-to-Noise Ratio in decibels
- `clipping` -- True if audio is clipped (distorted)
- `quality_label` -- Human-readable label: "excellent", "good", "fair", or "poor"

**Why it matters:**
Poor audio quality degrades all downstream AI models. If SNR drops below 8 dB, the agent reduces its confidence score and flags "low_audio_quality" as a risk signal. This helps operators know when microphone hardware needs maintenance.

### Task 7: Language and Accent Identification

| Property | Value |
|----------|-------|
| File | `tasks/accent_lang_id.py` |
| Model | SpeechBrain ECAPA-TDNN VoxLingua107 |
| Source | `speechbrain/lang-id-voxlingua107-ecapa` |
| Size | ~80 MB |
| Speed | ~0.5 seconds |
| Input | Raw audio waveform |

**What it does:**
Identifies which of 107 languages the speaker is using. The model was trained on the VoxLingua107 dataset covering languages from Afrikaans to Zulu. Accent detection is derived from the language model's confidence distribution across English-adjacent language variants (Welsh, Irish, Scottish, South African).

**Output fields:**
- `top_language` -- Detected language code (e.g., "en" for English, "es" for Spanish)
- `top_language_score` -- Confidence for the top language
- `all_language_scores` -- Top 10 language scores
- `top_accent` -- English accent variant (if applicable)

**Why it matters:**
Enables multilingual deployments. An edge device in an international facility can automatically detect what language is being spoken and route transcripts to the correct processing pipeline.

### Task 8: Environmental Sound Classification (ESC)

| Property | Value |
|----------|-------|
| File | `tasks/esc.py` |
| Model | MIT Audio Spectrogram Transformer (AST) |
| Source | `MIT/ast-finetuned-audioset-10-10-0.4593` |
| Size | ~350 MB |
| Speed | ~2 seconds |
| Input | Raw audio waveform |

**What it does:**
Classifies audio into 527 environmental sound categories from the AudioSet ontology. Categories include speech, music, vehicle sounds, animal sounds, nature sounds, alarms, sirens, gunshots, glass breaking, and hundreds more.

**Output fields:**
- `top_class` -- Most likely environmental sound (e.g., "Alarm", "Glass breaking")
- `top_score` -- Confidence score
- `top_5` -- Top 5 sound classifications with scores

**Why it matters:**
This is the primary threat detection model. The agent maintains an alert sound list including: alarm, siren, explosion, gunshot, glass breaking, crash, scream, shout, emergency, smoke detector, and fire. If any of these sounds are detected, the agent raises an "alert_sound" risk signal and can escalate to HIGH priority.

### Task 9: Acoustic Event Detection (AED)

| Property | Value |
|----------|-------|
| File | `tasks/acoustic_event_detection.py` |
| Model | PANNs MobileNetV2 ONNX (primary) / AST (fallback) |
| Source | Local ONNX checkpoint or MIT AST |
| Size | ~14 MB (ONNX) or ~350 MB (AST fallback) |
| Speed | ~8 milliseconds (ONNX) |
| Input | Raw audio waveform resampled to 32kHz |

**What it does:**
Similar to ESC but optimized for real-time detection using a lightweight MobileNetV2 architecture. Returns top-k acoustic events with frame-level timestamps. Falls back to the heavier AST model if the ONNX checkpoint is not available.

**Output fields:**
- `events` -- List of detected acoustic events with labels, scores, and time ranges
- `frame_labels` -- Top 5 event labels for the current frame

**Why it matters:**
Provides a second, independent confirmation of environmental sounds. When both ESC and AED agree on an alert sound, the agent's confidence increases significantly.

### Task 10: Audio Quality Monitor

| Property | Value |
|----------|-------|
| File | `tasks/audio_quality_monitor.py` |
| Model | Custom DSP (no neural network) |
| Source | Built-in signal processing |
| Size | 0 MB |
| Speed | Less than 1 millisecond |
| Input | Raw audio waveform |

**What it does:**
Monitors the technical health of the audio stream. Computes MOS, SNR, and checks for clipping. Produces a quality verdict: excellent, good, fair, or poor.

**Output fields:**
- `mos` -- Mean Opinion Score (1.0 to 5.0)
- `snr_db` -- Signal-to-Noise Ratio in decibels
- `clipping` -- Boolean clipping detection
- `quality_label` -- "excellent", "good", "fair", or "poor"

**Why it matters:**
Serves as a hardware health check. Consistent "poor" readings indicate a broken microphone, excessive background noise, or improper installation. The memory system tracks repeated quality degradation and escalates automatically.

### Task 11: Music / Speech Detection

| Property | Value |
|----------|-------|
| File | `tasks/music_speech_detection.py` |
| Model | Custom DSP (zero-crossing rate + spectral features) |
| Source | Built-in signal processing |
| Size | 0 MB |
| Speed | Less than 1 millisecond |
| Input | Raw audio waveform |

**What it does:**
Determines whether the audio contains primarily music, speech, or silence using zero-crossing rate analysis and spectral feature extraction. Does not use any neural network.

**Output fields:**
- `classification` -- "music", "speech", or "silence"
- `confidence` -- Confidence in the classification

**Why it matters:**
Helps the agent decide which follow-up tasks are relevant. If the audio is music, running ASR (speech transcription) would be wasteful.

### Task 12: Anomaly Detection

| Property | Value |
|----------|-------|
| File | `tasks/anomaly_detection.py` |
| Model | Statistical outlier detection (autoencoder-style) |
| Source | Built-in algorithms |
| Size | 0 MB |
| Speed | ~3 seconds |
| Input | Raw audio waveform |

**What it does:**
Computes a statistical profile of the audio and compares it against expected patterns. If the audio deviates significantly from the baseline (unusual spectral distribution, abnormal energy levels, unexpected frequency patterns), it flags the window as anomalous.

**Output fields:**
- `is_anomaly` -- True if the audio is flagged as anomalous
- `anomaly_score` -- Negative values indicate stronger anomalies (threshold: -0.10)

**Why it matters:**
Catches audio events that no specific model was trained to detect. A machine malfunction, an unusual vibration, or an unrecognized sound pattern would all be flagged here. The agent uses this as a "catch-all" risk signal.

---

### Task 13: Impulse Event Detector

| Property | Value |
|----------|-------|
| File | `tasks/impulse_event.py` |
| Model | Custom DSP (crest factor + transient analysis) |
| Source | Built-in signal processing |
| Size | 0 MB |
| Speed | Less than 1 millisecond |
| Input | Raw audio waveform |

**What it does:**
Detects short, sharp impulse events such as gunshots, slamming doors, impacts, or explosions. Uses crest factor (peak-to-RMS ratio), transient detection, and high-frequency band energy analysis.

**Output fields:**
- `is_impulse` -- True if an impulse event was detected
- `event_label` -- Classification: "gunshot_or_explosion", "impact", or "normal_audio"
- `confidence` -- Confidence in the classification
- `crest_factor` -- Peak-to-RMS ratio (higher = sharper impulse)
- `transient_ratio` -- How much the audio energy changed between frames
- `high_band_ratio` -- Percentage of energy in high-frequency bands

**Why it matters:**
Gunshots and explosions produce distinctive acoustic signatures with very high crest factors and sudden energy spikes. This task runs in under 1 millisecond and immediately escalates to HIGH priority if an impulse event is detected.

## Agent Decision Engine

The agent (`agent/audio_agent.py`) is a rule-governed decision engine that fuses all task outputs into a single actionable decision. It does NOT use a large language model. It operates purely on deterministic rules and configurable thresholds.

### Decision Flow

```
Step 1: Extract Signals
    Read outputs from all completed tasks.
    Compute: speech_detected, low_quality, anomaly, impulse,
             stress_emotion, alert_keyword, transcript_alert,
             esc_event

Step 2: Classify Event
    Based on signal combinations:
    - 2+ risk signals        --> "possible_safety_incident" (HIGH)
    - Impulse event detected  --> "possible_impulse_threat" (HIGH)
    - Anomaly or alert sound  --> "acoustic_risk_event" (MEDIUM)
    - Speech with transcript  --> "speech_workflow_event" (MEDIUM)
    - Speech without text     --> "speech_detected" (LOW)
    - Environmental sound     --> "environmental_audio_event" (LOW)
    - Nothing notable         --> "normal_audio" (LOW)

Step 3: Estimate Confidence
    Start at 0.35 base score.
    Add points for: successful tasks, speech detection, transcripts,
                    ESC events, stress emotions, risk signals.
    Subtract points for: low audio quality.
    Final range: 0.00 to 0.98.

Step 4: Privacy Decision
    LOW/MEDIUM events  --> metadata only (no raw audio exported)
    HIGH events        --> metadata + redacted transcript
    Privacy-first mode --> never export raw audio

Step 5: Recommend Action
    HIGH   --> "create_incident_and_notify_operator"
    MEDIUM --> "store_metadata_and_request_review"
             or "extract_intent_and_route_to_workflow"
    LOW    --> "ignore_or_continue_monitoring"
             or "log_event"
```

### Risk Signal List

The agent tracks these risk signals:

| Signal | Trigger |
|--------|---------|
| `low_audio_quality` | Audio quality label is "poor" or SNR below 8 dB |
| `audio_anomaly` | Anomaly score below -0.10 (not explained by speech) |
| `impulse_event` | Crest factor and transient analysis detect a sharp impact |
| `stressed_speech` | Emotion is angry, fearful, or sad above 45% confidence |
| `alert_keyword` | Keyword like "stop", "help", "fire" detected above 50% |
| `transcript_alert` | Transcript contains explicit safety/distress language |
| `alert_sound` | ESC detects alarm, siren, gunshot, glass breaking, etc. |
| `timeline_escalation` | Memory system detects repeated risk pattern |

## Agent Policies

The agent supports four pre-built policy profiles:

### Balanced (Default)

- Always runs: VAD, audio quality, anomaly detection, impulse detection
- On speech: follows up with ASR and emotion
- On no speech: follows up with ESC
- On high risk: follows up with ESC, keyword spotting, speaker ID
- Max parallel tasks: 6

### Industrial Safety

- Same as balanced but adds ESC to the always-on list
- Lower thresholds for ESC alerts (0.20) and stress detection (0.40)
- On speech: adds keyword spotting to follow-up
- Designed for factory floors and hazardous environments

### Privacy First

- Minimal task set: VAD, audio quality, anomaly, impulse
- On speech: only ASR (no emotion, no speaker ID)
- Raw audio export permanently disabled
- Max parallel tasks: 4
- Designed for GDPR-compliant deployments

### Low Power

- Smallest task set: VAD, audio quality, impulse
- Skips anomaly detection from always-on (runs only as follow-up)
- Max parallel tasks: 3
- Designed for battery-powered or Raspberry Pi devices

## Memory and Timeline System

The memory system (`agent/memory.py`) provides persistent, cross-session event tracking.

### What Gets Stored

Every decision is saved as a single JSON line in `agent_memory/events.jsonl`:

```json
{
  "timestamp": "2026-05-07T02:43:07.123456+00:00",
  "event_type": "acoustic_risk_event",
  "priority": "medium",
  "confidence": 0.64,
  "recommended_action": "store_metadata_and_request_review",
  "privacy_mode": "metadata_only",
  "risk_signals": ["audio_anomaly"],
  "models_used": ["anomaly_detection", "audio_quality_monitoring", "impulse_event"],
  "transcript": "",
  "summary": "acoustic_risk_event / medium: anomaly detector flagged unusual audio",
  "source": "",
  "metadata": {
    "policy": "balanced",
    "speech_ratio": 0.0,
    "quality_label": "fair",
    "snr_db": 10.6,
    "transcript": ""
  }
}
```

### Timeline Intelligence

The memory system does not just store events. It actively influences future decisions:

1. **Lookback Window** -- Scans the last 600 seconds (10 minutes) of events
2. **Related Event Detection** -- Finds past events with the same type or overlapping risk signals
3. **Escalation Logic** -- If a MEDIUM event follows a recent HIGH event, or if the same risk signal appears repeatedly, the system automatically escalates the current event
4. **Quality Tracking** -- If "poor" or "fair" audio quality appears 2 or more times in the window, it flags hardware degradation

### Privacy Guarantees

- Raw audio is NEVER stored in memory
- Transcripts are only stored if the policy explicitly allows it AND the event is HIGH priority
- Speaker embeddings are never exported
- All data stays on the local device

## Output Schema Reference

### AgentDecision Fields

| Field | Type | Description |
|-------|------|-------------|
| `event_type` | string | Classification of the audio event |
| `priority` | string | "low", "medium", or "high" |
| `confidence` | float | Agent confidence (0.00 to 0.98) |
| `recommended_action` | string | What the operator should do |
| `privacy_mode` | string | Data export policy applied |
| `models_used` | list | Names of all tasks that ran |
| `reasoning` | list | Human-readable explanation of the decision |
| `follow_up_tasks` | list | Tasks the agent recommends running next |
| `risk_signals` | list | Active risk flags |
| `data_export` | dict | What data is allowed to leave the device |
| `task_health` | dict | Status of each task ("ok" or error message) |
| `metadata` | dict | Additional context (speech ratio, SNR, transcript) |

### Event Types

| Event Type | Priority | Meaning |
|-----------|----------|---------|
| `possible_safety_incident` | HIGH | Multiple risk signals detected simultaneously |
| `possible_impulse_threat` | HIGH | Gunshot, explosion, or sharp impact detected |
| `acoustic_risk_event` | MEDIUM | Anomaly or alert sound without full confirmation |
| `speech_workflow_event` | MEDIUM | Speech with transcript available for processing |
| `speech_detected` | LOW | Speech heard but no transcript or risk signals |
| `environmental_audio_event` | LOW | Non-speech sound classified (music, nature, etc.) |
| `normal_audio` | LOW | No notable activity |

## Practical Use Cases

### 1. Industrial Safety Monitoring

Deploy on factory floors to detect:
- Machinery malfunctions via anomaly detection
- Explosions or impacts via impulse detection
- Worker distress calls via emotion + keyword spotting
- Unauthorized personnel via speaker identification

**Recommended batch:**
```bash
python fast_run.py --agent --tasks vad,asr,emotion,impulse_event,anomaly_detection,esc
```

### 2. Building Security

Deploy in corridors, lobbies, or restricted areas:
- Glass breaking via ESC (alert_sound signal)
- Gunshots via impulse detection
- Verbal distress ("help", "stop") via ASR + keyword spotting
- Unusual sounds at unusual times via anomaly detection

**Recommended batch:**
```bash
python fast_run.py --agent --tasks vad,asr,keyword_spotting,esc,impulse_event,anomaly_detection
```

### 3. Smart Office / Meeting Room Analytics

Deploy in conference rooms for:
- Meeting transcription via ASR
- Speaker count via speaker identification
- Sentiment analysis via emotion detection
- Background noise quality via audio quality monitoring

**Recommended batch:**
```bash
python fast_run.py --agent --tasks vad,asr,speaker_id,emotion,speech_quality,audio_quality_monitoring
```

### 4. Environmental / Wildlife Monitoring

Deploy outdoors for:
- Animal sound classification via ESC
- Music vs. nature vs. human activity via music/speech detection
- Unusual event detection via anomaly detection
- Acoustic logging via AED

**Recommended batch:**
```bash
python fast_run.py --agent --tasks esc,acoustic_event_detection,anomaly_detection,music_speech_detection
```

### 5. Multilingual Call Center / Help Desk

Process recorded calls for:
- Automatic language detection via lang_accent_id
- Caller emotion tracking via emotion detection
- Full transcription via ASR
- Call quality scoring via speech quality

**Recommended batch:**
```bash
python fast_run_file.py --file "call_recording.wav" --agent --tasks vad,asr,lang_accent_id,emotion,speech_quality
```

### 6. Post-Incident Audio Forensics

Analyze recorded audio files after an incident:
- Full transcription with timestamps
- Speaker identification and counting
- Emotion timeline reconstruction
- Environmental sound identification
- Impulse event confirmation

**Recommended batch:**
```bash
python fast_run_file.py --file "incident_audio.wav" --agent --tasks vad,asr,speaker_id,emotion,esc,impulse_event,anomaly_detection
```

## Airgapped Office Deployment via GitHub Releases

Because corporate networks often block HuggingFace, USB drives, and personal cloud storage, but **allow GitHub**, we use GitHub Releases to bypass size limits and transfer the models.

### Step 1: Prepare on Personal Unrestricted PC
1. Ensure all models are downloaded to the models/ folder.
2. Run python split_for_github.py to split the massive models.zip file into chunks under 1.5 GB (e.g., models.zip.part1, models.zip.part2).
3. Push the framework code to your GitHub Repository (models/ is ignored by .gitignore).
4. Open your GitHub Repository in a web browser, go to **Releases**, create a new Release, and drag-and-drop the .part files to attach them.

### Step 2: Deploy on Restricted Office Linux PC
1. Open the terminal and clone the code: git clone https://github.com/Yogendra-A/edge_audio_framework.git
2. Open the office web browser and download the .part files from your GitHub Releases page.
3. Stitch the split zip files back together in the terminal:
   `ash
   cat models.zip.part1 models.zip.part2 > models.zip
   `
4. Extract the models: unzip models.zip
5. Setup the Python environment and run offline:
   `ash
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   python fast_run.py --agent --tasks vad,asr,emotion,speaker_id
   `
